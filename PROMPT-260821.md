# Prompt para Desarrollo de Aplicación Mobile: ATTCONTROL

Actúa como un desarrollador Full Stack sénior y arquitecto de software móvil. Tu objetivo es crear la aplicación móvil **ATTCONTROL**, una plataforma administrativa moderna, rápida, segura e intuitiva para el control de asistencia de personal de una empresa pequeña.

## RESUMEN TÉCNICO
- Nombre de la App: ATTCONTROL
- Logotipo: icon_1024.png, icon_512.png, icon_256.png, icon_128.png, icon_64.png
- Horario usual:
  - Lunes a viernes: entrada  7:00 a.m. y salida 5:00 p.m
  - Sábados: 8:00 a.m. a 12:00 m.

---

## 1. Stack Tecnológico Recomendado
- **Frontend / App Móvil:** Flutter (con soporte para iOS y Android) usando **Riverpod** para la gestión de estado.
- **Backend / Base de datos:** Supabase / Firebase (Autenticación, PostgreSQL/NoSQL DB, Edge Functions / Cloud Functions).
- **Persistencia local (Offline-first):** SQLite o Hive / Drift para almacenamiento de marcas en local sin conexión.

---

## 2. Requisitos de Experiencia de Usuario (UI/UX)
- **Estilo visual:** Limpio, moderno e intuitivo, orientado a operarios de campo y administrativos.
- **Paleta de colores:** Identidad corporativa en verde bosque profundo (`#1B5E3B`), verde claro/menta (`#C8E6C9`) y fondo blanco o neutro para garantizar alto contraste.
- **Usabilidad:** Operación con un solo toque (*1-Tap Check-in*) con retroalimentación háptica y visual inmediata.

---

## 3. Funcionalidades Clave
### A. Autenticación y Seguridad
- Inicio de sesión por correo/contraseña, número de documento o biometría (Fingerprint / Face ID).
- Gestión de roles de usuario: **Super Admin**, **Supervisor de Campo**, **Empleado**, **Asesor**, **Contratista**.

### B. Registro de Asistencia (Check-In / Check-Out)
- Botón principal de marcación rápida de entrada y salida.
- **Geolocalización (GPS):** Captura obligatoria de coordenadas al momento del fichaje para validar que el personal esté en el sitio asignado.
- **Modo Offline:** Permitir marcas sin conexión a internet y sincronizar automáticamente en segundo plano cuando haya cobertura.
- **Verificación:** Escaneo de código QR en el carnet, el código QR arroja el número del documento de identidad (id), el cual corresponderá al identificador único para la creación y gestión en la base de datos de cada persona. Esta opción estará habilitada para los roles **Super Admin** y **Supervisor de Campo**.
- **Vacaciones y permisos:** Las personas con rol **Empleado** tendrán acceso a un panel de solicitud de permisos y programación de vacaciones, las cuales deberán ser aprobadas por el supervisor o administrador.

### C. Módulo de Administración y Reportes (Para Supervisores)
- Panel con lista de personal en tiempo real (Presentes, Ausentes, Llegadas tardías). Desde este panel se podrá agregar, editar y eliminar personal. Tendrá al menos los siguientes campos para asignar a cada persona: ID, NOMBRE, APELLIDO, CARGO, CORREO ,RH, EPS, ARL, ROL. Usar como datos iniciales los cargados en el archivo "ATTCONTROL_BD.xlsx".
- Exportación de reportes de asistencia en PDF y Excel/CSV filtrados por fecha, proyecto o cuadrilla.
- Aprobación o justificación de novedades (incapacidades, permisos, horas extras, vacaciones).
- Panel de control para definición del calendario laboral, horarios laborales y % de recargo de hora extra. Por defecto definir los valores que aplican para Colombia según la ley vigente:
  - **Periodo de corte salarial**: Semanal, Quincenal o Mensual.
  - **hora_entrada**: 7:00 a.m.
  - **hora_salida**: 5:00 p.m.
  - **hora_entrada_sabado**: 8:00 a.m.
  - **hora_salida_sabado**: 12:00 m.
  - **Jornada diurna**: Va desde las 6:00 a.m. hasta las 7:00 p.m.
  - **Jornada nocturna**: Va desde las 7:00 p.m. hasta las 6:00 a.m. del día siguiente.
  - **Porcentajes de Recargo y Horas ExtrasHora extra diurna**: 25% de recargo sobre la hora ordinaria.
  - **Hora extra nocturna**: 75% de recargo sobre la hora ordinaria.
  - **Recargo nocturno ordinario**: 35% extra si se labora de noche dentro del turno normal.
  - **Trabajo dominical o festivo (ordinario)**: 90% de recargo sobre la hora ordinaria.
  - **Hora extra diurna en domingo o festivo**: 105% de recargo.
  - **Hora extra nocturna en domingo o festivo**: 155% de recargo.
- Definir el calendario laboral según el vigente para Colombia (se deben identificar los días domingo y festivos para efectos de cálculo de las horas extra)
- Los usuarios con rol **Empleado** solo podrán visualizar sus horas registradas, agrupadas según el **Periodo de corte salarial.**. Además tendrán acceso al panel de solicitud de permisos y vacaciones, el cual tendrá tabla resumen con el historial y el estado de cada permiso o vacaciones (pendiente, aprobado, rechazado, cumplido).
- Los usuarios con rol **Contratista** y **Asesor** solo podrán visualizar sus horas registradas. NO tienen acceso aplica el panel de solicitud de permisos y vacaciones.

## 4. Arquitectura y Rendimiento
- Aplica la arquitectura limpia (*Clean Architecture*) separando capa de presentación, dominio y datos.
- Maximiza la velocidad de carga de la app (pantallas respondiendo en menos de 100ms).
- Encriptación de datos sensibles tanto en tránsito (HTTPS/WSS) como en reposo (AES-256).

---

## 5. Tablas Principales y Campos (este es un esquema propuesto, el cual se puede mejorar)
* empleados (Datos personales y laborales)
 - id (PK, INT)
 - codigo_empleado (VARCHAR, único)
 - nombre (VARCHAR)
 - apellido (VARCHAR)
 - departamento_id (FK)
 - turno_id (FK)
 - activo (BOOLEAN)
* departamentos (Áreas o secciones de la organización)
 - id (PK, INT)
 - nombre (VARCHAR)
* turnos (Horarios asignados)
 - id (PK, INT)
 - nombre (VARCHAR)
 - hora_entrada (TIME)
 - hora_salida (TIME) [1]
* asistencia_registros (El marcaje principal de entrada/salida)
 - id (PK, INT)
 - empleado_id (FK)
 - fecha (DATE)
 - entrada (DATETIME, opcional)
 - salida (DATETIME, opcional)
 - tipo_registro (ENUM: 'biometrico', 'web', 'manual')
 - estado (ENUM: 'a tiempo', 'tarde', 'falta', 'salida temprana') [1, 2, 3]
* incidencias (Permisos, vacaciones o justificaciones)
 - id (PK, INT)
 - empleado_id (FK)
 - tipo (ENUM: 'permiso', 'vacaciones', 'enfermedad', 'justificado')
 - fecha_inicio (DATE)
 - fecha_fin (DATE)
 - comentario (TEXT)
